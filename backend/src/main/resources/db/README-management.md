# 내 약 관리·챗봇 기능 확장 (2026-09-22)

## 사용자 기능

- 현재 등록 약 / 복용 중 / 보관 중 / 확인 필요 / 복용 안 함 / 종료된 기록 필터.
- 등록 건별 복용 상태 저장. 현재 처방과 활성 상시약도 사용자의 확인 전에는 복용 중으로 단정하지 않음.
- 종료된 처방 기록, 오늘을 포함한 처방 기간 잔여일, 제품 사진·제조사.
- 약별 챗봇 이동 및 두 제품을 함께 전달하는 링크.
- 빈 목록에서 기존 메인 페이지 처방전 등록 모달로 이동.
- 챗봇의 선택 약 추천 질문, 내 등록 제품 선택, 검색으로 비교 대상 추가.
- 확인된 복용 중 제품들의 DUR 비교, 제품 간 같은 성분 표시, 미연결 제품/성분 안내.
- 자연어 '내 등록 약', '내 약끼리 같이 먹어도 돼?'를 로그인 사용자 범위로 조회.

## DB 변경

`20260922_medication_use_states.sql`로 MEDICATION_USE_STATES 테이블을 현재 개발 DB에 생성했다. 동일 DB에서는 재실행하지 않는다. 다른 개발 DB에는 한 번 적용해야 한다.

- PK: USER_ID + REGISTRATION_ID(P:/C:/R: 접두사와 기존 등록 ID).
- USE_STATUS: ACTIVE, PAUSED, ENDED, STORED.
- 사용자 외래키와 상태 CHECK 제약. 쓰기는 해당 사용자가 소유한 등록 건에만 허용.
- 기존 처방전/상비약/상시약 테이블의 내용을 수정하지 않음.
- 처방 기간이 끝나면 이전 ACTIVE 표시보다 종료 상태가 우선한다. 미래 처방은 시작 전으로 분류.
- 이 화면에서의 상태 관리는 처방 용량이나 캘린더 알림을 변경하지 않는다.

## 비교 범위

등록 건이 여러 개여도 같은 제품은 한 번만 비교한다. 서로 다른 제품에 각각 존재하는 A/B 성분이 병용금기 원문에 일치하는 경우만 표시하며 역방향도 확인한다. 최대 50개 제품까지 비교한다.

성분은 공백과 대소문자를 정규화한 정확 일치만 사용한다. 제품 미연결/성분 없음/DUR 기록 미연결을 구분해 표시한다. 조회 결과가 없다고 안전함을 의미하지 않는다.

## 검증

- 전체 백엔드 Java 21 컴파일.
- 관리 기능 27개(실제 Oracle SQL, 읽기 전용 CTE 기간/상태 데이터, 다른 사용자 차단, DUR 비교 등).
- 기존 질문 분류 23개, Gemini 계약 23개, 등록 약 조회 7개 통과.
- 실제 Gemini 개인 목록/병용 조회 표현 3개 확인.
- 수정한 가이드/챗봇 ESLint, 프론트 Vite 빌드 통과.
- 브라우저의 가상 API 데이터로 상태 저장 표시, 기간 종료 필터, 제품 전달, 두 제품 비교 화면 검증. 실제 사용자 복약 데이터는 테스트에서 변경하지 않음.

## 실행

Eclipse에서 Project Build 후 Tomcat Publish/재시작, 브라우저 새로고침 및 로그인. 복용 중 여부를 지정하면 상단 DUR 비교에 반영된다. 이번 코드는 소스에 반영되어 있으며 현재 실행 중인 Tomcat에 자동 재배포하지 않았다.
