# 2026-10-07 프리뷰·등록·알림 재점검

## 요청과 확인 환경

- PC: `http://127.0.0.1:4173`, Vite preview → `/api` → Tomcat 8080
- 모바일 신고 환경: iPhone Brave. 다른 계정이 남긴 커뮤니티 반응도 앱 종료 상태에서 수신되지 않음
- 범위: 전체 자동 검사, 조회 API·인증·가족 접근 권한, 등록, 커뮤니티, 챗봇, 내 약 관리, PWA·푸시
- 개인 데이터 삭제나 실제 사용자 대상 푸시 없이 검사. DB 쓰기 검사는 합성 행을 생성하고 전부 롤백

## 발견 원인과 수정

### 상비약·영양제 등록

등록 화면이 대상자의 표시 이름을 `username`으로 보냈고 서버는 로그인 ID로 해석했다. 올바른 userId가 있어도 표시 이름이 달라 403이 발생했다. 포트 4173 문제가 아니었다.

- 불필요한 username 전송 제거. 대상자의 숫자 ID와 서버 세션·가족 권한으로 판단
- 등록 요청 중 중복 제출 차단, 입력 비활성화, 목록 갱신 완료 후 잠금 해제
- 401·403·HTML 오류·success:false를 성공으로 처리하지 않음
- 잘못된 대상자 ID와 사라진 제품은 400으로 거부
- 가족 대상 변경 시 입력·조회 상태를 초기화하고 늦게 도착한 이전 응답 제외

### 앱 종료 후 커뮤니티 알림

기존 커뮤니티는 user_notifications 알림함 기록만 만들었고 Web Push 전송 경로가 없었다.

- 커밋된 댓글·답글·글/댓글 도움 표시·신고·관리자 처리 결과를 기기별 푸시 큐로 전달
- 본인 행동 제외. 기기 연결 후 최근 10분 이내 생성된 읽지 않은 알림만 대상
- 발송 직전 로그인 계정·기기 구독·알림 전체 설정·관리자 권한을 다시 확인
- 중복 발송 방지, 일시 실패 최대 3회 재시도, 만료된 구독 제거
- Oracle UTC 벽시각과 한국 JVM 시간대 바인딩 차이를 수정
- 실제 iPhone 재검증에서 테스트 알림만 도착한다는 피드백으로 기존 구독의 한국 벽시각 created_at 문제를 추가 확인. 댓글 UTC 시각보다 9시간 뒤로 비교돼 발송 대기열이 비어 있었음
- 기존 구독의 시각을 추측해 덮어쓰지 않고 UTC 기준 community_started_at 컬럼 추가. 기존 기기는 기능 이행 이후, 새 기기는 구독 이후에 생긴 커뮤니티 알림만 대상. DB 이행 완료
- 권한 재조회 결과가 MyBatis 캐시에 남지 않도록 처리
- 서비스 워커에 커뮤니티 알림 수신·게시글/관리자 화면 이동 추가. 이동 주소 허용 목록 적용
- 잠금 화면에는 약 이름·게시글·댓글·신고 본문을 노출하지 않음
- `/api/push/config`의 `communityEnabled`로 복약/커뮤니티 준비 상태 분리
- 가족 초대는 별도 저장소를 쓰므로 이번 커뮤니티 푸시 대상에 포함되지 않음

### 성분 연결 누락

medication_ingredients가 0건이었다. 기존 마이그레이션은 정규화 결과가 같은 원문을 중복 INSERT해 PK 충돌할 수 있었다.

- 제품·정규화 성분 키로 먼저 묶고 MERGE하는 별도 복구 SQL 추가
- 기존 사용자 약·처방전·영양제·검증 별칭을 변경하지 않고 공개 파생 연결만 복구
- 실제 DB 복구: 91,398건, 기존 검증 별칭으로 91,398건 연결
- 임부 주의정보에 연결되는 제품: 12,848건. 복용 추천이나 모든 위험의 완전한 검출을 의미하지 않음
- 신규 품목 동기화 인덱싱은 NESTED 저장점을 사용해 미커밋 품목을 같은 연결에서 조회
- 개별 오류가 이후 모든 품목 인덱싱까지 영구 중단하지 않도록 수정
- 공개 파생 테이블·인덱스의 통계를 갱신하고 이전 실행계획 즉시 무효화. 검색 시간 제한은 유지
- guide mapper의 SELECT DISTINCT와 ORDER BY 표현식 불일치(ORA-01791) 수정. 검증된 별칭의 주의 근거가 fallback으로 누락되던 문제 해결

### 전체 프런트 검사에서 발견한 추가 문제

- 날짜 없는 실시간 복약 이벤트가 다른 함수의 todayStr을 참조하던 ReferenceError 수정
- 캘린더·가족·공용 날짜 선택기 닫기 시 하위 연도 메뉴 정리
- 날짜 선택기 위치 측정을 첫 화면 표시 전 수행
- 알림 날짜 유틸과 DialogProvider import 경계를 정리. 린트 억제 규칙 추가 없음
- 320px 챗봇에서 공통 body 최소 너비가 스크롤바 공간까지 밀어내던 가로 넘침 수정

## 휴대폰에서 최종 확인할 절차

1. iPhone Safari에서 현재 HTTPS 주소 접속 → 공유 → 홈 화면에 추가
2. 홈 화면 아이콘으로 열어 A계정 로그인 → 마이페이지 → 이 기기 알림 켜기
3. 테스트 알림이 해당 휴대폰에 오는지 확인
4. 로그아웃하지 않고 앱을 닫기
5. 다른 브라우저 또는 기기의 B계정에서 A의 글에 새 댓글 또는 도움 표시
6. 서버가 실행 중일 때 알림 도착·클릭 후 해당 글 이동 확인

같은 브라우저에서 A를 로그아웃하고 B로 바꾸면 A의 해당 기기 구독이 해제된다. PC 구독은 휴대폰 구독을 대신하지 않는다. 터널 주소가 바뀌면 새 출처에서 설치·로그인·알림 연결을 다시 확인한다.

## 확인 한계

사용자가 iPhone 테스트 알림 수신을 확인했고, 첫 댓글 재검증에서는 미수신을 보고했다. 기존 구독의 시각 문제를 수정하고 서버에 반영한 뒤 실제 커뮤니티 알림 도착을 최종 확인했다. Android 실기기 수신은 별도 미확인이다. 브라우저 크기 검사는 iOS 실기기 검사와 다르다. 실제 처방전 개인정보를 OCR/외부AI에 전송하거나 테스트 도구로 실제 사용자에게 푸시·메일을 보내는 검사는 수행하지 않았다. 실제 DB 롤백 검사에도 Oracle sequence 번호 증가분은 남을 수 있다.
