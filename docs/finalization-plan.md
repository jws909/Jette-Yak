브라우저 화면 크기를 바꾼 검사는 실제 휴대폰 키보드 검증을 대신하지 않는다. PWA는 빌드 + preview에서 동작하며, Android 앱 프로젝트는 만들지 않았다. 실행·휴대폰 HTTPS 테스트 순서는 [PWA 안내](pwa.md)를 참고한다.

### 알림의 현재 동작 범위

`frontend/src/App.jsx`는 페이지에서 매분 복약 시간을 확인한다. 모바일에서는 활성 서비스 워커의 알림 표시를 우선 사용하고, 실패해도 앱 내부 모달은 이어서 표시한다. 상단 알림함은 `Navbar.jsx`에서 30초마다 조회한다. 앱을 닫거나 화면이 잠긴 상태에서도 알림을 보장하는 푸시·네이티브 예약 기능은 구현되어 있지 않다.

## 1. 취합·전체 테스트

### 이번 점검에서 직접 실행한 항목

- `npm test`: 88개 통과 (기존 38개 + PWA 50개)
- `npm run test:flows`: 56개 통과
- `npm run build`: 통과. 큰 JavaScript 청크에 대한 경고는 남아 있음
- 전체 ESLint: 오류 22개·경고 4개. 테스트 통과와 별개로 정리 필요
- PWA와 이번 연결 수정 파일 대상 ESLint: 통과

이 숫자는 프런트 테스트 결과다. 전체 서비스·외부 API·실제 휴대폰 검증 완료를 뜻하지 않는다. 기존 기록은 `tools/qa/2026-10-07-site-check.md`에서 확인하고, 최종 결과서는 다시 실행한 결과로 갱신한다.

### 우선 해결할 코드·동작

1. OCR 실패 처리: `VisionOcrService.java`가 외부 API 실패 또는 빈 인식 결과를 샘플 처방전으로 대체한다. 정상 저장 흐름으로 들어갈 수 있으므로 실제 업로드 검증 전에 실패 안내로 구분해야 한다.
2. 업로드 안내·제한: `PrescriptionTab.jsx`의 PDF·15MB 안내와 실제 이미지 전용 선택, 서버의 전체 multipart 요청 12MiB 제한을 일치시켜야 한다.
3. 알림 오류: `Navbar.jsx`의 미정의 `todayStr` 등 ESLint 오류를 실제 기능과 함께 점검한다.
4. 서버 검증: 로그인 세션, 본인·가족·관리자 권한, 잘못된 입력, 중복 요청, 저장 실패·재시도 흐름을 확인한다.
5. 외부 연동: 메일, Google Vision OCR, Gemini, 공공 데이터 API를 모의 테스트와 실제 연동으로 구분해 기록한다.
6. 최종 브랜치와 커밋을 확정하고, 이후 화면 변경 시 자료·영상·테스트 결과에도 반영한다.
